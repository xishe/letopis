# Летопись: прототип как B2B SaaS (дизайн)

Дата: 2026-10-20. Автор решений: команда «Летописи» (Климент), детали без пометки «решение команды» — выбор ассистента, их можно оспорить.

## Зачем
Текущий прототип на Streamlit доказывает логику (CSV → кандидаты → черновик), но выглядит как студенческое демо. Для питча на курсе нужен прототип, который жюри воспринимает как настоящий B2B SaaS-продукт.

**Решения команды:**
- Важнее дизайн, а не бэкенд. Бэкенд может быть фейковым.
- Визуальный стиль — как Linear, но в **светлых тонах**.
- Главный экран — вариант B «Хроника»: лента результатов по неделям и месяцам, сверху находки автосбора с кнопкой «Подтвердить».
- Аудитория — жюри курса на питче. Демо: прокликать путь до готового self-review за 2–3 минуты.
- Строят агенты на модели Sonnet, при необходимости несколько параллельно.
- Публикация в сети через Netlify; репозиторий на GitHub пользователя.
- Нужен фирменный стиль: логотип и сопутствующее.

## Цели
1. Сквозной кликабельный путь «подключили источники → хроника → подтвердили результат → собрали self-review → отправили руководителю» без единого тупика.
2. Ощущение продукта: аккуратная типографика, плотные списки, горячие клавиши, плавные микроанимации, реалистичные данные.
3. Каждое утверждение в self-review ведёт к записи и её подтверждениям — это главный тезис продукта, он должен быть виден на экране.
4. Публичная ссылка на Netlify, которую можно открыть с любого ноутбука на питче.

## Не цели
- Настоящая авторизация, база данных, интеграции с Jira/GitLab/Confluence/Контур.Толк, LLM-вызовы.
- Мобильная версия (достаточно, чтобы не ломалось на ширине от 1280 px; ниже — приемлемо, но не цель).
- Тёмная тема.

## Анти-цели (провал, даже если работает)
- Выглядит как шаблон админки или Streamlit: стандартные виджеты, яркие градиенты, «радужные» дашборды.
- Демо зависает, требует интернета кроме самой загрузки страницы, ключей или ручной подготовки перед показом.
- Пустые экраны и «Lorem ipsum»: все тексты на русском, правдоподобные.
- Обещания, которых нет в исследовании (например, «экономит 90% времени» как факт). Цифры экономии — с пометкой «по анкетам, n=5» или как цель.

## Ограничения
- Windows, Node 24, npm. Статическая сборка (SPA), деплой на Netlify как статический сайт.
- Данные демо — инженер «Иван Петров», backend, период апр–сен 2026, 164 задачи Jira и 52 MR; берутся из существующих `data/demo_jira.csv` и `data/demo_gitlab.csv` и группировки из `letopis/grouping.py` (15 кандидатов). Конвертируются в JSON скриптом на этапе разработки.
- Состояние демо — в памяти и `localStorage`, с кнопкой «Сбросить демо».

## Стек (выбор ассистента)
Vite + React + TypeScript + Tailwind CSS, иконки lucide-react, анимации framer-motion, роутинг react-router (HashRouter не нужен — на Netlify правило SPA-редиректа). Шрифт Inter (самостоятельно размещённый через `@fontsource/inter`, чтобы демо не зависело от Google Fonts). Без UI-китов вроде MUI — компоненты свои, чтобы не выглядело шаблонно.

Код — в `letopis_prototype/web/`. Streamlit-версия остаётся как есть.

## Фирменный стиль (выбор ассистента)
- **Логотип:** монограмма «Л» из двух линий, правая ножка продолжается в вертикальную «нить времени» с тремя точками-отметками (результаты, зафиксированные по ходу). Скруглённый квадрат 6 px радиуса, заливка акцентом, знак белый. SVG, плюс favicon и вордмарк «Летопись» (Inter Semibold, межбуквенный −1%).
- **Палитра (светлая, «Linear-like»):** фон приложения `#FBFBFC`, сайдбар `#F4F4F6`, поверхности `#FFFFFF`, границы `#E6E6EA`/`#EEEEF1`, текст `#1B1C1F`, вторичный `#6B6C72`, приглушённый `#8A8B91`. Акцент — индиго `#5E5CE6` (свой, не копия Linear). Статусы: подтверждено `#2F9E6B` на `#E9F6EF`, не хватает эффекта `#B2681C` на `#FDF1E6`, предложено — серый пунктир.
- **Типографика:** Inter, базовый 13 px в приложении, заголовки 15–20 px Semibold, моноширинные id (`R-12`, `LET-212`) в tabular-nums.
- **Иконки источников:** нейтральные чипы «Jira», «GitLab», «Confluence», «Толк», «Grafana» (текстовые, без чужих логотипов).
- Сопутствующее: OG-картинка для ссылки (1200×630), заставка загрузки, пустые состояния с короткой иллюстрацией из линий в стиле логотипа.

## Экраны и демо-путь
Порядок прокликивания на питче (≈2,5 мин):

1. **Лендинг** `/` — один экран: вордмарк, заголовок «Один раз зафиксировали результат — используйте во всех отчётах», 3 тезиса из исследования (с пометкой n=5), кнопка «Открыть демо». Внизу «On-premise · SSO · LLM в контуре компании».
2. **Подключение источников** `/app/onboarding` — карточки Jira, GitLab, Confluence, Контур.Толк с кнопками «Подключить» (фейк: спиннер → «Подключено»), выбор периода, кнопка «Собрать хронику» → анимация «Нашли 164 задачи и 52 MR → 15 результатов» (≈2 с).
3. **Хроника** `/app/chronicle` — вариант B. Сайдбар: Входящие (счётчик находок), Хроника, Отчёты, Инициативы (заглушка «скоро»), раздел «Команда Backend» с «Цикл ревью H1 · 12 дн.». Лента по месяцам; сверху пунктирные карточки автосбора («Подтвердить» / «Добавить эффект» / «Скрыть»). Статус-кружки и плашки эффекта как в макете. Горячие клавиши: `C` — записать результат, `⌘K`/`Ctrl+K` — палитра команд, `J/K` — навигация по ленте.
4. **Карточка результата** (боковая панель справа поверх хроники) — название, описание, поле «Эффект» с подсказкой, найденная автосбором цифра («Возможный эффект: p95 800→450 мс» → кнопка «Использовать»), список источников (задачи и MR со ссылками-заглушками), «Добавить подтверждение» (ссылка на дашборд или отзыв), переключатель видимости «Видит руководитель» (приватность по умолчанию: выкл.).
5. **Сборка self-review** `/app/reports/new` — шаг 1: шаблон формата компании (выбор из 2: «Self-review H1 (Acme)», «Свободный»), шаг 2: отбор результатов чекбоксами с индикатором «7 из 9 подтверждены», кнопка «Собрать черновик».
6. **Черновик** `/app/reports/:id` — документ, который «печатается» потоково (имитация генерации, 3–4 с, можно пропустить). Каждое утверждение с маленькими сносками-чипами `[R-1]`; наведение подсвечивает запись, клик открывает её панель. Справа — **чек-лист готовности** из исследования: «Есть подтверждения ключевых утверждений», «Понятно описан личный вклад», «Получена обратная связь руководителя» + метрики «Подготовка: 14 мин» и «Пункты с подтверждённым эффектом: 7/7». Кнопки «Отправить руководителю» (модалка с выбором → тост «Отправлено Анне Смирновой») и «Скачать .md».
7. **(Если хватит времени) Команда** `/app/team` — сводка тимлида: результаты команды с подтверждениями (только расшаренные авторами), чтобы показать ценность для покупателя.

Сценарий данных: при старте 15 результатов, из них 9 уже «подтверждены» (с эффектом), 3 «без цифры», 3 — свежие находки автосбора. Так в демо есть что подтвердить и есть что собрать.

## Данные, тексты и интерактивность (решения ассистента после проверки ревьюером)
- **Источник тезисов и цифр — исследование команды**, `C:\Users\Kliment\Documents\ОПП\Летопись_контекст.md` (разделы 5–8). Использовать только оттуда. Тезисы лендинга: «4 из 5 не вели записей в течение периода», «3 из 5 назвали восстановление результатов самым трудным этапом», «5 из 5 потратили на подготовку время других задач; у 3 из 5 первая версия и правки — по 10+ ч». Подпись: «опрос 5 инженеров, 2026». Пункты чек-листа готовности — ровно три критерия респондентов: «Есть подтверждения ключевых утверждений», «Понятно описан личный вклад», «Получена обратная связь руководителя». Метрика «Подготовка: N мин» — реальный таймер демо-сессии (от «Собрать хронику» до готового черновика), а не заявленная экономия.
- **Курированный фикстур.** Конвертер берёт 15 кандидатов из `letopis/grouping.py` + демо-CSV и пишет `web/src/data/demo.json`; затем фикстур правится вручную (это часть этапа 1): человеческие названия вместо «Работы по теме «label»», хвост «Поддержка и исправления» скрыт по умолчанию. Статусы: 9 эпиков с «Возможный эффект» → «подтверждено», эффект = эта цифра в коротком виде; «Онбординг», «security-audit», «observability-cleanup» → «нет цифры»; три одиночных результата (дедупликация CRM, email-уведомления, экспорт CSV) → «находки автосбора» с датами в последние 2 недели. Где в CSV нет цифры у «подтверждённых», эффект дописывается правдоподобно в фикстуре.
- **Согласование чисел.** Счётчики считаются из фикстура, не хардкодятся: задач Jira = 164 (без строк Epic), MR = 52, результатов = 15 (14 видимых + хвост). Цикл ревью называется «Ревью · осень 2026» (период апр–сен). Индикатор сборки: «N из M выбранных подтверждены»; метрика черновика: «Пункты с подтверждённым эффектом: N/M» по тем же выбранным.
- **Интерактивность настоящая (в памяти).** Общий стор (zustand, с сохранением в localStorage) создаётся на этапе 1 с фиксированным API: `results`, `confirm(id)`, `setEffect(id, text)`, `addEvidence(id, url)`, `setVisibility(id, bool)`, `hide(id)`, `createReport(templateId, resultIds) → reportId`, `reports`, `sendReport(id, to)`, `resetDemo()`, `session.startedAt`. «Подтвердить» меняет статус и счётчик «Входящих»; добавленный эффект попадает в сборку и черновик. Агенты 2a и 2b только вызывают стор, логику стора не меняют.
- **Черновик собирается из выбранных результатов** шаблонным генератором (без LLM) с имитацией потоковой печати. Шаблон «Self-review (Acme)»: разделы «Ключевые результаты», «Личный вклад», «Влияние на команду и продукт», «Что дальше». «Свободный» — плоский список. Снятие галочки и пересборка меняют текст. Утверждения без эффекта помечаются «⚠ добавьте эффект» и отражаются в чек-листе.

## Критерии готовности
- `npm run build` без ошибок и предупреждений TypeScript.
- Демо-путь 1→6 проходит в браузере без ошибок в консоли, на ширине 1280 и 1440 px.
- «Сбросить демо» возвращает начальное состояние.
- Публичная ссылка на Netlify открывается, прямые ссылки на `/app/...` работают (SPA-редирект).

## На усмотрение исполнителя
Точные отступы, анимации, тексты пустых состояний, формулировки черновика (в рамках демо-данных), структура компонентов.
